# tests: the filter test material

Upstream only: this folder is not part of the shipped payload, and adopting workspaces carry no test material. The root README navigates here; read this page before maintaining the filters or the pairs.

## Why this exists

The stream filters are byte-sensitive: one edited branch silently changes what every session sees, and nothing errors when it does. This folder is their regression net, adapted from rtk's strongest practice: static input and expected-output pairs, byte-compared by the harness. It is hermetic (POSIX sh, awk, cmp, mktemp; no toolchain, no installs, no network). The subject under test is the shipped core: the core suites run the base runtime (`base/.contexture/ctx`) and its modules, never the live drawer (the storage compliance harness is handed base's posix driver by path); the plugin suites exercise each plugin's own copy under `plugins/<name>/`, never the adopted copy in the live drawer, because the two drift. Every harness stages its sandbox under the workspace's gitignored `.contexture/tmp/` when that drawer is writable, and falls back to TMPDIR only when it is not; each run makes a sandbox of its own (mktemp, never a fixed name) and keeps its locks, stores, and scratch inside it, because the runner starts the suites concurrently and two gates may run at once.

## What is here

- `run.sh`: the runner: every core suite (the session suite twice, `core:session-tests.sh` on the posix driver and `core:session-tests.sh:fts5` on the fts5 driver, and `core:base-only-tests.sh`, the shipped base alone), then every plugin suite by convention (`plugins/<name>/tests/run.sh`; the docs-discipline suite twice as well, `plugin:docs-discipline` on posix and `plugin:docs-discipline:fts5` with `--driver=fts5`, skip 77 without sqlite3 FTS5), one line per suite plus a final verdict; non-zero when any suite fails; a suite exiting 77 (a need absent) reports SKIP. The suites run concurrently: each is a background job with its own output file in one gate scratch folder, its exit code written by the job itself (never read through a pipeline); when all have ended the runner prints every suite's output and outcome line in the fixed order above, then the suite times and the verdict. A suite still running after `GATE_SUITE_TIMEOUT` seconds (default 1200) is stopped with its whole process tree and fails; `GATE_JOBS=<n>` caps how many run at once (`GATE_JOBS=1` runs the suites one after another, same order, same output; the session suite still runs its groups at once inside its own run).
- `filter-tests.sh`: the filter harness. It pipes each `.in` through the runner (`ctx run --filter=<filter>`), byte-compares the output with the `.expected`, and fails when a filter carries no pair (the presence check). It also drives the mechanics cases: the ANSI strip, command identity in runner mode, the notice-only false-green output, and the recovery fallback to raw.
- `ctx-tests.sh`: the engine suite: discovery, assembly, dispatch, the run mechanics, shadow and bad-header sandboxes, the ideas module when the live drawer carries it.
- `session-tests.sh [--driver=posix|fts5] [--group=1|2|3|all]`: the session suite, its sections in three groups that share no unit, run at once by default (each group in its own sandbox, the outputs printed in group order under one summary line), one group with `--group=<n>`, or every section in one sandbox in order with `--group=all`: verbs, refusals, paging, refs, refresh rc semantics, helper fallbacks, the dual-driver defect regressions, payload fidelity (newlines and backslash sequences reach the block verbatim, a carriage return refuses), backslash payloads on every awk (a backslash, a doubled backslash, a literal backslash n, and a trailing backslash read back byte for byte from every typed write), one-line fields (an embedded newline in a one-line field refuses, a WHAT carrying double quotes records and reads back verbatim, a legacy two-line WHAT still loads), one quote rule (a quoted state objective, next pointer, added and updated task OBJECTIVE land and read back verbatim, the newline refusals kept), the retired verbs (append, amend, query, flip, drop each rc 1 naming its replacement, their names reserved), the verbs added in v0.55.0 (entry closure, units, refs-to, lane create; `ctx session migrate` an unknown verb), path-free messages (every verb warning and error names the artifact and its unit, never a sessions path; entry.record answers its refs), the capability handshake at dispatch (a planted contract 2 driver lacking a record function refuses rc2, a complete one is verified once per driver change), the storage failure tier (a read-only store refuses rc2 and changes nothing, and the store comes back whole once its files are writable again), interrupt cleanup (a TERMed method leaves no scratch), the parallel-write probe, the base input checks of the end review (section E3: the two REF shapes and their edges in E7-R (a lone `/`, a trailing `/`, `./`, a control byte or a Unicode blank refused; `###`, `/abs/file`, `../x` landing), bytes that are not UTF-8 or a NUL refused naming the field, the stamp taking the unit alone; the closer form in C, the required search mode in X). It writes the record through the verbs and reads it through the verbs and the storage functions (`lib/plant.sh`), so the same assertions run on either driver; the cases that need legacy text (shapes only a hand-written file holds) plant it as posix files and run on posix alone, each saying so; `--driver=fts5` stages the plugin's own module copy and writes `storage.driver: fts5` into its sandbox config, and skips 77 when sqlite3 lacks FTS5. A verb that bypasses the driver turns the fts5 run red.
- `base-only-tests.sh [--keep]`: the shipped base alone, with no plugin. It stages `base/` only (no `docs/`, no `plugins/`, no config, no rhythms directory) and proves the payload a bare adoption carries: the no-plugin help surface (lane, session, storage listed; docs and storage-fts5 unknown rc 1), the absent-rhythms index rc 0 with an empty answer (with and without the directory), the posix descriptor at 43 functions (38 record plus 5 store, exact, optional store), the record, lane, and store smoke over a synthetic data module (bootstrap through close and reopen, tasks, journal with a closer, findings, lane create/record/report/show, board, load to completion, audit, exact search, resolve of every entity, entry closure, fold, stamp, next, refresh), the store data-file grammar and the five functions over a synthetic namespace (the exact answers, the key rule, the case twin, the refusals, the no change log on posix, no temp or lock residue), the no-base-to-docs census with a planted reference, and the posix core suites (filter, ctx, session, hook, record-audit, storage compliance over base's driver, and store compliance through `--data-file`). The descriptor check and the census are null-checked by a planted difference (a missing record function, a missing store function, a planted docs reference). It excludes the fts5 session run, the docs suite, and every plugin suite by design: those are plugin gates. The gate reads red on BG1 before the index fix and green after (journal of 2026-10-28).
- `storage-compliance.sh [--driver-exec=<path>] [--census[=<file>]]`: the storage contract suite (contract 2, docs/the-engine.md The storage contract), 65 cases in 18 suites on posix and 59 on every other backend, passed through the driver executable alone: the wire (the escaped payload with indexed lists, one compact JSON answer in the contract key order, one fixed stderr line per refusal), the 38 record functions (`unit.export` and `unit.import` refused as unknown), the record rules (a CLOSED unit refusing every write, the status moves, the pointer rule, receipts, suffixed slugs, positional liveness, the audit checks), the canonical layout (no answer carries stored bytes; a legacy item's content in typed fields) and the append rule, the exact search rule; every case asserts the data returned, never an exit code alone, and `--census` lists any case that would (it answers none); a fixture a backend can hold is built through the functions, the same calls on every backend held to the same read answers (TC76's unit against its goldens in `fixtures/compliance/golden/verb-u/`), and the legacy text only a hand-written file holds is planted as posix files from `fixtures/compliance/units/` in the six posix-alone cases (TC57, TC60, TC64, TC69, TC77, TC78), which with TC61's posix journal bytes and TC79's stray lane folder (a lanes/<lane> folder without an artifact is no lane) are the only cases touching a store directly; the corpus cases of v0.54.0 (TC40 to TC46, TC50, TC51) retired with the docs corpus port, and the docs plugin suite proves the corpus over the generic store; suite 12 stages the shipped resolver with planted contract 2 descriptors (TC47 to TC49: `require` and `has` for the optional capabilities and `search.mode.<m>`, the verdict cache, the handshake refusing a missing function or contract). Against a v0.54.0 driver only the corpus cases pass.
- `store-compliance.sh [--driver=posix|fts5] [--driver-exec=<path>] [--data-file=<path>] [--keep]`: the generic module store compliance suite (contract 2, the storage module's store contract), S1 to S8 over the five functions. - `parity-v054.sh --old=<base> --new=<base> --units=<sessions dir> --out=<dir> [--unit=<u>]... [--jobs=N] [--views=<list>] [--bytes]`: the kept-view parity harness (never in the gate: a manual proof): two staged posix sandboxes over copies of the same units, one base per side (the v0.54.0 base against the branch; its store-driver options retired with the dump, since no command fills another backend from the unit copies), and per unit every kept text view compared by content with its exit code (board, the load with every page of each side joined, audit, refresh, task list, entry list, finding list, exact search over a fixed query set of 12, resolve of every task, finding, and entry, lane show of every lane artifact): every item reads in one canonical layout, so a side printing an item as stored and a side printing it canonical compare by their content signatures (`lib/content.awk`, the one content comparator: it drops carriage returns, blank lines, trailing blanks, the load's page scaffolding, the field order across labels, a block or a line for one value, the quoting of WHAT, OBJECTIVE, REF, the spelling of a REFS list, a closer, an anchor, a state key's continuation, a search result's snippet, and keeps every value and every line no field holds), `--bytes` comparing the bytes instead; a difference is allowed only by a named class (quote-layout: the double quote query, whose matches are quoting; with `--bytes`, write-scope: a load differing by its WRITE SCOPE line alone), every other one is the remainder, and the run exits 0 only when the remainder is 0; stderr differences are reported beside.
- `lib/plant.sh`: the record fixtures and reads of the verb suites: `rsum` checksums a unit as its read functions answer it (on posix with its files too), on every driver; `rcat`, `rput`, `rappend` read and plant legacy text as the posix files of the workspace under test and refuse rc 3 on another driver, whose store holds only what the verbs write.
- `hook-tests.sh`: the hook engine suite over the committed fixture modules in `fixtures/hooks/`; every shipped hook point fires.
- `record-audit-tests.sh`: the audit's planted-defect matrix, one case per defect class the audit owns.
- `governance-tests.sh`: the main-surface forbid grep, the payload path tables re-derived against `git ls-files`, the presence checks (verbs, hook points, filters, gate lines), and G5: no `sub` or `gsub` replacement in the awk and sh files of base, the plugins' module copies, and the suites carries a backslash before a character other than a backslash or `&` (`lib/awkrepl.awk`, null-checked by a planted file).
- `lib/awkrepl.awk`: the replacement census of G5: every `sub` or `gsub` replacement literal whose value carries a backslash before another character, one line per hit (Debian's busybox awk drops that backslash).
- `<filter>-<case>.in` / `<filter>-<case>.expected`: a real captured stream and the exact bytes the filter must emit.
- `compact-recovery.awk`: a synthetic probe filter for the recovery mechanics case.
- `fixtures/`: committed fixtures for the non-filter suites (hook modules, the ideas dump, and `fixtures/compliance/`: the legacy markdown units the posix-alone cases plant (`units/`), the legacy fixture's golden answers and item notes (`golden/legacy-u/`, `legacy.notes`), the verb-built unit's golden answers (`golden/verb-u/`, written from posix with `COMPLIANCE_WRITE_GOLDENS` and read by hand), the exact search answers of TC39 and TC69, and TC61's expected posix journal).
- `lib/jflat.awk`: the JSON reader the storage suites share (an answer flattened to path and value lines, a JSON string decoded to its bytes).
- `lib/content.awk`: the content comparator of text views: a capture's content signature, blind to layout (every item reads in the one canonical layout, so a proof across layouts compares content, never bytes); `parity-v054.sh` compares by it; `VIEW=load` drops the WRITE SCOPE line each page repeats, `VIEW=search` a result's snippet.

Plugin pairs live under the plugin (`plugins/toolchain-filters/tests/`) and run through a staged sandbox. The docs-discipline suite (`plugins/docs-discipline/tests/run.sh [--driver=posix|fts5]`) stages from `base/` and its own copies and carries, on each driver, the staging check, the audit, the unit-form nudge, the write verbs, the engine checks, the delta-source cases (the check's store and git modes, `ctx docs changes`, the gate's two halves), the single-door census, the gate matrix, and the grammar agreement check; its fts5 run adds the store seed (every staged doc through `ctx docs write`), the stored bytes (every doc read back unchanged through `ctx docs write --replace --dry-run`), and the capture parity against the files driver at one sandbox path, and runs its corpus checks in a second sandbox beside that chain (its module README carries the detail). The storage-fts5 suite (`plugins/storage-fts5/tests/run.sh`) runs on the plugin's own module copy: `test-driver.sh` (the compliance suite through `--driver-exec`), `test-schema.sh` (schema 4 laid in a new or empty file; a store at another version refused naming it, untouched, no backup), `test-verbs.sh` (one verb sequence on posix and fts5 in a workspace staged from `base/`, the views equal, the store's typed fields, and `ctx storage-fts5 migrate` and `ctx session migrate` answering unknown verbs), `test-version.sh` (the sqlite3 3.44 guard of the record functions and of `storage.health` under a fake sqlite3), and `test-derive.sh` (the per-part derive of every write against a whole rebuild, and the lines table against the posix files of the same writes); each skips 77 without sqlite3.

## Roots

Core pairs (this folder):

- `diff-show-trimmed`: a `git show` of a long commit message.
- `list-ansi`: a colored `ls` capture (ANSI-bearing).
- `log-repeat`: a repeated-line log capture.
- `compact-false-green`: a tsc shim emitting a JS TypeError (mechanics case).
- `compact-recovery`: synthetic input plus its probe (mechanics case).

Plugin pairs: see `plugins/toolchain-filters/tests/README.md`.

## How to maintain

- The ship gate: `tests/run.sh` must end green before any commit, tag, or push; a red run holds the ship breath. The runner reports one line per suite plus a final verdict, a planted failure must exit non-zero, and a planted hang must end as a failure at the suite timeout with no process left behind.
- A new suite (core or plugin) stages in a sandbox of its own (mktemp under the scratch drawer, removed on exit) and never writes a fixed name or a path outside it: the runner starts every suite at once, so a shared path turns into a race.
- A base change (a module script, the resolver, the store, a help surface) runs the base-only gate as well: `tests/base-only-tests.sh`, and the ship gate runs it as `core:base-only-tests.sh`; a base-only regression that passes the plugin suites must fail there.
- A filter change is not done until the harness passes: `tests/filter-tests.sh`.
- A new filter is not done until it carries at least one pair; the presence check fails otherwise.
- Update a `.expected` only with evidence: rerun the capture or reproduce the behavior. Never hand-edit an expected to match a surprise.
- Keep the pairs static and hermetic; a `.in` is a capture, never a live command.
- Portability: the suite carries no awk of its own choosing; it runs under whatever awk the system has. Before a change to an awk encoder, decoder, or regex string ships, run `tests/run.sh` under each supported awk (BWK awk on macOS, and in disposable Linux containers Debian with its default mawk, Debian with gawk, Alpine with busybox awk, with sqlite3 and git inside the container for the fts5 run and the governance probe); an assertion that only one awk turns red is the reason the matrix exists.
