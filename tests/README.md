# tests: the filter test material

Upstream only: this folder is not part of the shipped payload, and adopting workspaces carry no test material. The root README navigates here; read this page before maintaining the filters or the pairs.

## Why this exists

The stream filters are byte-sensitive: one edited branch silently changes what every session sees, and nothing errors when it does. This folder is their regression net, adapted from rtk's strongest practice: static input and expected-output pairs, byte-compared by the harness. It is hermetic (POSIX sh, awk, cmp, mktemp; no toolchain, no installs, no network). The subject under test is the shipped core: the core suites run the base runtime (`base/.contexture/ctx`) and its modules, never the live drawer (the storage compliance harness is handed base's posix driver by path); the plugin suites exercise each plugin's own copy under `plugins/<name>/`, never the adopted copy in the live drawer, because the two drift. Every harness stages its sandbox under the workspace's gitignored `.contexture/tmp/` when that drawer is writable, and falls back to TMPDIR only when it is not; each run makes a sandbox of its own (mktemp, never a fixed name) and keeps its locks, stores, and scratch inside it, because the runner starts the suites concurrently and two gates may run at once.

## What is here

- `run.sh`: the runner: every core suite (the session suite twice, `core:session-tests.sh` on the posix driver and `core:session-tests.sh:fts5` on the fts5 driver), then every plugin suite by convention (`plugins/<name>/tests/run.sh`; the docs-discipline suite twice as well, `plugin:docs-discipline` on posix and `plugin:docs-discipline:fts5` with `--driver=fts5`, skip 77 without sqlite3 FTS5), one line per suite plus a final verdict; non-zero when any suite fails; a suite exiting 77 (a need absent) reports SKIP. The suites run concurrently: each is a background job with its own output file in one gate scratch folder, its exit code written by the job itself (never read through a pipeline); when all have ended the runner prints every suite's output and outcome line in the fixed order above, then the suite times and the verdict. A suite still running after `GATE_SUITE_TIMEOUT` seconds (default 1200) is stopped with its whole process tree and fails; `GATE_JOBS=<n>` caps how many run at once (`GATE_JOBS=1` runs the suites one after another, same order, same output; the session suite still runs its groups at once inside its own run).
- `filter-tests.sh`: the filter harness. It pipes each `.in` through the runner (`ctx run --filter=<filter>`), byte-compares the output with the `.expected`, and fails when a filter carries no pair (the presence check). It also drives the mechanics cases: the ANSI strip, command identity in runner mode, the notice-only false-green output, and the recovery fallback to raw.
- `ctx-tests.sh`: the engine suite: discovery, assembly, dispatch, the run mechanics, shadow and bad-header sandboxes, the ideas module when the live drawer carries it.
- `session-tests.sh [--driver=posix|fts5] [--group=1|2|3|all]`: the session suite, its sections in three groups that share no unit, run at once by default (each group in its own sandbox, the outputs printed in group order under one summary line), one group with `--group=<n>`, or every section in one sandbox in order with `--group=all`: verbs, refusals, paging, refs, refresh rc semantics, helper fallbacks, the dual-driver defect regressions, payload fidelity (newlines and backslash sequences reach the block verbatim, a carriage return refuses), backslash payloads on every awk (a backslash, a doubled backslash, a literal backslash n, and a trailing backslash read back byte for byte from every typed write), one-line fields (an embedded newline in a one-line field refuses, a WHAT carrying double quotes records and reads back verbatim, a legacy two-line WHAT still loads), one quote rule (a quoted state objective, next pointer, added and updated task OBJECTIVE land and read back verbatim, the newline refusals kept), the retired verbs (append, amend, query, flip, drop each rc 1 naming its replacement, their names reserved), the verbs added in v0.55.0 (entry closure, units, refs-to, lane create, migrate between two stores), path-free messages (every verb warning and error names the artifact and its unit, never a sessions path; entry.record answers its refs), the capability handshake at dispatch (a planted contract 2 driver lacking a record function refuses rc2, a complete one is verified once per driver change), the storage failure tier (a read-only store refuses rc2 and changes nothing, and the store comes back whole once its files are writable again), interrupt cleanup (a TERMed method leaves no scratch), the parallel-write probe. It reads and writes the record only through the verbs and the storage functions (`lib/plant.sh`), so the same assertions run on either driver; `--driver=fts5` stages the plugin's own module copy and writes `storage.driver: fts5` into its sandbox config, and skips 77 when sqlite3 lacks FTS5. A verb that bypasses the driver turns the fts5 run red.
- `storage-compliance.sh [--driver-exec=<path>] [--census[=<file>]]`: the storage contract suite (contract 2, docs/the-engine.md The storage contract), 70 cases in 19 suites (62 on a driver without `corpus.store`) that every backend passes through its driver executable alone: the wire (the escaped payload with indexed lists, one compact JSON answer in the contract key order, one fixed stderr line per refusal), the 40 record functions, the record rules (a CLOSED unit refusing every write, the status moves, the pointer rule, receipts, suffixed slugs, positional liveness, the audit checks), the verbatim and append rules, the exact search rule, the dump round trip; every case asserts the data returned, never an exit code alone, and `--census` lists any case that would (it answers none); fixtures load through `unit.import` from `fixtures/dumps/`, and only TC64 (the posix grammar plants) and TC61 (the posix journal bytes) touch posix files; suite 12 is the corpus store, unchanged from v0.54.0 (TC40 to TC46, TC50, TC51, keyed on the declared `corpus.store`, one refusal case in place of nine without it); suite 13 stages the shipped resolver with planted contract 2 descriptors (TC47 to TC49: `require` and `has` for the optional capabilities and `search.mode.<m>`, the verdict cache, the handshake refusing a missing function or contract). Against a v0.54.0 driver only the corpus cases pass.
- `parity-v054.sh --old=<base> --new=<base> --units=<sessions dir> --out=<dir> [--unit=<u>]... [--jobs=N] [--old-driver=<d>] [--new-driver=<d>] [--plugins=<dir>] [--views=<list>]`: the kept-view parity harness (never in the gate: a manual proof): two staged sandboxes over copies of the same units, one base per side (the v0.54.0 base against the branch, or one driver against another), and per unit every kept text view compared byte for byte with its exit code (board, every load page, audit, refresh, active, task list, entry list, finding list, exact search over a fixed query set of 12, resolve of every task, finding, and entry, lane show of every lane artifact); a difference is allowed only by a named class (write-scope: a load page differing by its WRITE SCOPE line alone), every other one is the remainder, and the run exits 0 only when the remainder is 0; stderr differences are reported beside.
- `lib/plant.sh`: fixture planting for the verb suites: `rcat`, `rput`, `rappend`, `plant_unit` read and write a unit's markdown through `unit.export` and `unit.import` and a posix staging workspace inside the sandbox (`$SANDBOX/.plant`), so every driver receives the same legacy shapes and no suite writes an artifact of the store under test.
- `dump-check.sh [<dump-file>]`: validates a dump (one compact JSON object per line, known kinds, the required fields in contract key order, the unit line first and the end line last, the record count, version 1) and names the first bad line.
- `hook-tests.sh`: the hook engine suite over the committed fixture modules in `fixtures/hooks/`; every shipped hook point fires.
- `record-audit-tests.sh`: the audit's planted-defect matrix, one case per defect class the audit owns.
- `governance-tests.sh`: the main-surface forbid grep, the payload path tables re-derived against `git ls-files`, and the presence checks (verbs, hook points, filters, gate lines).
- `<filter>-<case>.in` / `<filter>-<case>.expected`: a real captured stream and the exact bytes the filter must emit.
- `compact-recovery.awk`: a synthetic probe filter for the recovery mechanics case.
- `fixtures/`: committed fixtures for the non-filter suites (hook modules, the ideas dump, and `fixtures/dumps/`: the storage contract dumps with the legacy fixture's golden answers and item notes, the exact search answers, the TC64 posix plants, and under `tools/` the markdown sources and the fixture tools that regenerate them, `sh tests/fixtures/dumps/tools/build.sh`, which the suite never runs).
- `lib/jflat.awk`: the JSON reader the storage suites share (an answer flattened to path and value lines, a JSON string decoded to its bytes).

Plugin pairs live under the plugin (`plugins/toolchain-filters/tests/`) and run through a staged sandbox. The docs-discipline suite (`plugins/docs-discipline/tests/run.sh [--driver=posix|fts5]`) stages from `base/` and its own copies and carries, on each driver, the staging check, the audit, the unit-form nudge, the write verbs, the engine checks, the delta-source cases (the check's store and git modes, `ctx docs changes`, the gate's two halves), the single-door census, the gate matrix, and the grammar agreement check; its fts5 run adds the store seed and the migration round trip (both through `ctx session migrate --corpus`) and the capture parity against the files driver at one sandbox path, and runs its corpus checks in a second sandbox beside that chain (its module README carries the detail). The storage-fts5 suite (`plugins/storage-fts5/tests/run.sh`) runs on the plugin's own module copy: `test-driver.sh` (the compliance suite through `--driver-exec`), `test-upgrade.sh` (the in-place upgrade of a version 3 store), `test-dump.sh` (`unit.export` and `unit.import` over `fixtures/dumps/`), and `test-session-migrate.sh` (`ctx session migrate` between posix and fts5 in a workspace staged from `base/`: units and the corpus both ways byte for byte, the refusals, and `ctx storage-fts5 migrate` answering an unknown verb); each skips 77 without sqlite3.

## Roots

Core pairs (this folder):

- `diff-show-trimmed`: a `git show` of a long commit message.
- `list-ansi`: a colored `ls` capture (ANSI-bearing).
- `log-repeat`: a repeated-line log capture.
- `compact-false-green`: a tsc shim emitting a JS TypeError (mechanics case).
- `compact-recovery`: synthetic input plus its probe (mechanics case).

Plugin pairs: see `plugins/toolchain-filters/tests/README.md`.

## How to maintain

- The ship gate: `tests/run.sh` must end green before any commit, tag, or push; a red run holds the ship breath. The runner reports one line per suite plus a final verdict, a planted failure must exit non-zero, and a planted hang must end as a failure at the suite timeout with no process left behind.
- A new suite (core or plugin) stages in a sandbox of its own (mktemp under the scratch drawer, removed on exit) and never writes a fixed name or a path outside it: the runner starts every suite at once, so a shared path turns into a race.
- A filter change is not done until the harness passes: `tests/filter-tests.sh`.
- A new filter is not done until it carries at least one pair; the presence check fails otherwise.
- Update a `.expected` only with evidence: rerun the capture or reproduce the behavior. Never hand-edit an expected to match a surprise.
- Keep the pairs static and hermetic; a `.in` is a capture, never a live command.
- Portability: the suite carries no awk of its own choosing; it runs under whatever awk the system has. Before a change to an awk encoder, decoder, or regex string ships, run `tests/run.sh` under each supported awk (BWK awk on macOS, and in disposable Linux containers Debian with its default mawk, Debian with gawk, Alpine with busybox awk, with sqlite3 and git inside the container for the fts5 run and the governance probe); an assertion that only one awk turns red is the reason the matrix exists.
