MUST docs/docs-are-code (universal, workspace)
  Every documented behavior change lands with its doc update in the same unit of work.
  evidence: .contexture/extensions/modules/docs/scripts/docs-audit.awk
  anti: Refactoring an API contract without updating the unit's corpus doc
  good: Updating the endpoint signature in code and, with ctx docs entry on the matching contract rule, the unit's corpus doc in the same change

MUST docs/prompt-to-doc (universal, workspace)
  Every task begins with a docs query before inspecting or reading code files.
  evidence: .contexture/extensions/modules/docs/scripts/query
  anti: Reading source files directly before querying the corpus
  good: Querying the corpus first (search or file owner), then reading the owning doc and its pitfalls

MUST docs/stop-gate (universal, workspace)
  Close transactions must pass ctx docs gate cleanly, enforcing syntax integrity, coverage completeness, and doc freshness.
  evidence: .contexture/extensions/modules/docs/scripts/gate
  anti: Closing a task or ending a session with modified code but unupdated documentation
  good: Chaining the audit and the check via ctx docs gate to verify coverage and zero stale docs before closing

MUST docs/authoring (universal, workspace)
  New documentation is authored map-first: the codebase is mapped to coherent units with scoped sources globs (never a folder-by-folder mirror), each unit is drafted per the docs module's grammar (a private asset the write verbs enforce) and written through the ctx docs write verbs (ctx docs write for a whole draft, ctx docs new and the block verbs for the rest), and the draft is verified before it lands (ctx docs audit for integrity, ctx docs check for coverage, ctx docs query for the projected read).
  evidence: ctx docs write
  anti: One doc per source folder with a glob for every leaf
  good: Coherent units mapped by domain and intent, with the docs module's grammar (enforced by the write verbs) as the shape authority

MUST docs/drift (universal, workspace)
  Drift is reconciled from the change delta, never from memory: the status-prefixed delta feeds ctx docs check with BOTH halves in one stream (the code delta from git and the corpus delta: the corpus paths of the same git delta under the files driver, ctx docs changes under a store driver); every affected doc is updated through the ctx docs write verbs in the same change, uncovered paths widen a unit's sources or open a new unit, and the audit and the check re-run clean before the doc change lands.
  evidence: .contexture/extensions/modules/docs/scripts/docs-check.awk
  anti: Shipping a code change and deferring its doc update to a later commit; or verifying with a pipeline that feeds the check the code delta alone: it reads every claimed file stale where a claimant is tracked, and CLEAN (PROCESS-OWNED) where none is, so its verdict says nothing about the docs
  good: Both halves in one stream, records split so a rename's old path surfaces as a dead source (the working command is in the README's two-sided delta paragraph); for an uncommitted working tree, ctx docs gate composes both halves by itself on every driver and needs no pipeline

MUST docs/greppable-evidence (universal, workspace)
  Document evidence using greppable code symbols, attributes, or configuration keys, never line numbers.
  evidence: .contexture/extensions/modules/docs/scripts/docs-audit.awk
  anti: evidence: 'controllers/feed.cs:42'
  good: evidence: 'OrderController.ListOrders'

MUST docs/fixed-pitfalls (universal, workspace)
  A fixed pitfall is removed (the doc describes current truth); the id retires, never recycled; a behavior change born of the fix lands as a contract @rule; a new pitfall only for a genuinely new surprise, new id; references re-point via a fresh journal entry recording the resolution (append-only; under the files driver git history holds the removed text).
  evidence: .contexture/extensions/modules/docs/scripts/docs-audit.awk
  anti: Reclassifying a fixed bug as a gotcha to preserve its journal anchor.
  good: Remove the fixed pitfall with ctx docs pitfall <id> --remove (the id retires), land the behavior as a contract @rule, and re-point refs from a fresh journal entry.

MUST docs/section-refs (universal, workspace)
  References name their target exactly: an entry by its id (rule slug, pitfall id, member), a block by its canonical section address, in-doc #<block> (for example #contract, #patterns, #members) or cross-doc <slug>.md#<block>.
  evidence: .contexture/extensions/modules/docs/scripts/query
  anti: (see contract) with no block address
  good: (see #contract); (see order-flow.md#pitfalls)
